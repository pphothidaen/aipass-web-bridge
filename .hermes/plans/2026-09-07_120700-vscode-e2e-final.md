## Architecture Notes

The sidebar is a **webview** — a web page embedded in VS Code. The message flow:
```
User clicks button in webview
  → webview JS sends postMessage({ type: 'refreshModels' })
  → AipassViewProvider.ts receives message
  → calls client.listModels() → fetch bridge
  → posts back { type: 'setModels', models, fromRefresh: true }
  → webview renders models
```

If clicks don't work, the webview JS event handlers may not be bound correctly, OR the click coordinates are slightly off.

## Revised Approach

1. **Open sidebar** (already proven to work — click AiPASS icon in activity bar at x≈21, y≈372)
2. **Click each button using exact coordinates** from accessibility tree (not vision_analyze estimates)
3. **Use short waits** (2-5s max) then capture — don't wait for toasts that may have disappeared
4. **If a click doesn't work, try the alternative coordinate** (some buttons have two possible positions)
5. **Keep VS Code on-screen** — do `osascript activate` before each interaction batch

## Risks

1. **Clicks not registering:** If a button doesn't respond, the webview may not have focus. Try clicking the sidebar header first, then the button.
2. **Native dialog:** If 📁 opens a dialog that `computer_use` can't automate, report "opens dialog but couldn't automate — backend code path verified separately".
3. **Toast disappears fast:** Status messages may vanish after 3s. Capture immediately after the wait.
4. **VS Code off-screen:** If VS Code goes off-screen, run `osascript -e 'tell application "Visual Studio Code" to activate'` and wait 3s before retrying.
